## Honest Feedback

Three pieces of friction slowed this delivery. First, `gh issue view` failed before returning data because GitHub deprecated the classic-Projects field that the CLI still requested; the REST endpoint gave the needed issue data, but the deviation needed explicit recording. Second, the first local validation route assumed Ruby and an `npm exec` module-resolution behavior that were not available. Switching to Prettier's YAML parser and a temporary pinned Picomatch installation was fast, but I should have validated the available tools before assembling a compound check. Third, the native `maw pr` command silently replays every command marked pass, so the first create attempt failed on the prose-only matrix label. I recovered by reading the checked-in implementation rather than bypassing it, but a preflight read of that command's evidence contract would have removed the extra loop.

## Lessons Learned

- Treat delivery verification metadata as executable interface data: before marking a command pass, ensure it can be rerun non-interactively from the worktree.
- For a docs-only CI optimization, model the risky condition as "any non-doc file changed"; this makes a mixed documentation/code change fail closed into the expensive gate.
- Preserve a named CI job when optimizing its internals, even where current branch protection is absent; configuration can be added later without reintroducing an ambiguous status surface.
